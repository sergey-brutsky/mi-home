# Тесты MiHomeLib

- `Devices/Mqtt`, `Devices/Gateway2`, `Devices/Miio` — свойства, события и команды устройств.
- `Gateways` — обнаружение устройств, маршрутизация сообщений, команды шлюзов и жизненный цикл.
- `Transports` — обмен через локальные сокеты и транспортные пакеты.
- `Discovery` — miio discovery и чтение данных шлюза через Telnet.
- `Protocols` — реестр устройств и обработка протокольных сообщений.
- `Helpers` — общие механизмы библиотеки и регрессионные сценарии.
- `Infrastructure` — базовые классы, моки, запись событий и логов; `Messages` и `Fakes` содержат сообщения и эмуляторы.

Каждый тест получает собственные экземпляры изменяемых объектов. Тесты устройств без шлюза используют `ProtocolDeviceTestBase`; тесты маршрутизации используют отдельную настройку транспортов. Асинхронный miio-транспорт настраивается напрямую для обоих вариантов публичного API.

Полный прогон:

```sh
dotnet test MiHomeUnitTests
```

Транспортные проверки с локальными сокетами:

```sh
dotnet test MiHomeUnitTests --filter Category=Integration
```

При проверке порядка действий используйте сигналы завершения. Короткие реальные интервалы остаются в тестах таймаутов, повторных запросов и фрагментации сетевых сообщений. Ошибки фоновых задач должны доходить до теста; завершение эмуляторов следует ожидать при очистке.

Матрица `Every_Click_Reaches_Only_Its_Button` заменила 22 частично дублирующихся проверки Opple: 20 сочетаний кнопок/нажатий четырёхкнопочной модели и две проверки одиночного нажатия двухкнопочной модели. Она сохраняет эти сценарии и дополнительно проверяет повторные сообщения и отсутствие событий других кнопок.

Ожидаемый список поддерживаемых моделей, протоколов, PDID и типов задан явно в `Protocols/SupportedDevicesTests.cs`. При добавлении поддержки обновляйте его осознанно. Диагностические сценарии перечисляются по этому списку без создания устройств во время обнаружения тестов.

`VerifyMethod` проверяет команду с id=1; для другого идентификатора используйте `VerifyMethodWithId`. Разные имена исключают неоднозначность между id запроса и числовым параметром команды. Суффикс Async для настройки транспорта не нужен: транспорт всегда асинхронный.

Тесты с фоновыми циклами используют `IAsyncLifetime`, а Telnet-эмулятор — `IAsyncDisposable`. Незавершённые операции ожидаются при очистке, ресурсы закрываются в `finally`.

BLE-сообщения из `SetupBleAsyncEventParams` по умолчанию имеют фиксированную отметку `1700000000`. Для сценариев порядка сообщений передавайте время явно. Тестовый логгер сохраняет снимок именованных полей и `{OriginalFormat}`, чтобы проверки структурированного логирования отличали шаблоны от готовых строк.

Проверки остановки и освобождения активного `SimpleTimer` используют короткое окно наблюдения, превышающее интервал таймера. Они проверяют отмену отсчёта до срабатывания; отмена уже выполняющегося обработчика не требуется.

Покрытие строк и ветвей библиотеки можно измерить установленным `coverlet.msbuild` (из корня репозитория):

```sh
dotnet test MiHomeUnitTests --no-restore /p:CollectCoverage=true /p:CoverletOutput=../artifacts/coverage/coverage /p:CoverletOutputFormat=cobertura '/p:Include=[MiHomeLib]*'
```

Отчёт `artifacts/coverage/coverage.cobertura.xml` исключён из Git. Показатели относятся к выполнению на `net10.0`; они не подтверждают поведение на остальных целевых платформах или физических устройствах. При анализе пропусков отдавайте приоритет входным данным и обработке ошибок, встречающимся при реальном обмене, а не достижению 100% защитных ветвей.

Проверки реестра представлены отдельными theory-случаями по протоколам и регистрациям. Ошибки асинхронных обработчиков можно ожидать через `ErrorRecordingLoggerFactory.ErrorRecorded`; событие вызывается после помещения исключения в очередь ошибок.
